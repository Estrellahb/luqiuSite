# 开发指南

这是一份面向 AI 开发入门阶段的基础知识 Wiki，整理开发过程中需要反复使用的概念、工具和方法。

内容暂分为三个部分：

1. AI 开发基础
2. 开发环境准备
3. 信息搜索与提问方法

## 一、AI 开发基础

### [为什么写这份 Wiki](/development/why-write-this-wiki)

2026 年可以说是 Agent 高速发展的一年。年初，OpenClaw，也就是人们口中的“龙虾”，迅速走红。许多人开始尝试自行部署 Agent，并分享各自的“养虾”经验。围绕 Agent 构建的各种工程实践也不断出现，从 Context Engineering、Harness Engineering 到 Loop Engineering，相关概念持续受到关注。

各家 AI 厂商也在推进自己的 Agent 产品和开发界面，试图在通用型 Agent 领域取得更大的应用空间。随着 AI 逐渐渗透到生活和工作的各个方面，软件开发方式也在发生变化。

不少开发人员已经很少亲自编写每一行代码。编写清晰的需求文档，配置合适的工具，设定明确的行为约束，再让 AI 参与开发、测试和部署，正在成为越来越常见的开发流程。

这正是编写这篇文章的原因：整理如何与 AI 进行更有效的交流，如何为 AI 提供清晰的任务边界，以及如何通过文档和规范引导 AI 完成开发工作。

AI 不应该被当作许愿机，期待它直接读取脑海中的想法，并将模糊的设想完全复刻出来。缺少明确约束的项目，最终很容易变成结构不清晰、行为难以预测、后续难以维护的黑盒。

更合理的做法，是让 AI 参与需求分析和项目设计过程。围绕一个初步想法，通过持续讨论逐步明确项目目标、功能范围和实现方式，最终形成完整的 PRD、接口文档、验收标准、设计规范和项目依赖说明。

当这些文档足够清晰时，AI 才能在明确的范围内开展开发工作，减少需求偏移，保持项目结构可控，并完成相对完整的功能实现。这也是 AI 开发过程中值得建立的一套基础工作方法。

后续基础概念将继续整理在本页面。
### AI 开发需要了解什么

一个常见的 AI 应用，通常由以下部分组成：

- **模型**：负责理解文本、生成内容、分析图片或执行其他智能任务。
- **模型接口**：应用调用模型的入口，通常通过 API 地址、密钥和请求参数完成调用。
- **应用程序**：负责接收用户输入、组织提示词、调用模型，并展示处理结果。
- **运行环境**：程序实际运行所依赖的操作系统、编程语言、软件包、网络和权限。
- **数据**：应用需要读取、处理或保存的内容，例如文档、网页、数据库记录和用户配置。
- **开发工具**：用于编写代码、管理文件、运行命令、查看日志和排查问题的软件。

AI 应用出现问题时，需要区分问题属于模型能力、提示词、接口配置、程序代码、依赖环境还是网络连接。建立这种区分能力，比记住某一条命令更重要。

### 基础概念

#### 编程语言

编程语言用于描述计算机需要执行的操作。AI 应用中常见的语言包括 Python、JavaScript 和 TypeScript。

- Python 常用于数据处理、模型调用、自动化脚本和后端服务。
- JavaScript 常用于网页交互，也可以通过 Node.js 编写服务端程序。
- TypeScript 在 JavaScript 的基础上增加类型检查，适合维护规模较大的项目。

#### 软件包与依赖

一个项目通常会调用其他开发者编写的软件包。软件包可能提供网络请求、文件处理、数据库连接或模型调用等功能。

项目运行前，需要根据项目配置安装对应依赖。依赖版本不一致、软件包缺失或安装位置错误，都可能导致程序无法启动。

#### API

API 是程序之间交换数据的接口。AI 应用一般通过 API 向模型服务发送请求，并接收模型返回的结果。

一次模型调用通常涉及：

- API 地址
- 身份认证信息
- 使用的模型名称
- 输入内容
- 生成参数
- 返回结果和错误信息

API 密钥属于敏感信息，不应直接写入公开代码、截图、文章或提交到 Git 仓库。

#### 命令行

命令行是通过文字命令操作电脑的方式。开发过程中经常使用命令行安装依赖、进入项目目录、启动服务、查看日志和执行构建任务。

命令执行前，需要确认当前目录、命令作用和可能产生的文件变化。遇到不熟悉的命令，应先查阅文档或确认参数含义。

#### Git

Git 用于记录代码和配置文件的修改历史。通过 Git 可以查看变更、恢复文件、创建分支，并与远程仓库同步项目。

基础使用通常包括：

1. 查看当前修改。
2. 阅读文件差异。
3. 提交已经确认的改动。
4. 使用分支隔离不同功能。
5. 推送到远程仓库或通过 Pull Request 合并。

## 三、信息搜索与提问方法

浏览器、搜索引擎、开发问题描述和 AI 提问方法，详见：[信息搜索与提问方法](/development/information-search-and-asking)。

### 如何使用搜索引擎

搜索的目标不是立刻找到一篇完整答案，而是定位可靠的资料、错误原因和可验证的解决步骤。

搜索关键词应包含具体对象和问题现象。例如：

- 不推荐：`代码运行不了`
- 推荐：`Python requests SSL certificate verify failed`
- 不推荐：`怎么安装 node`
- 推荐：`Node.js official installation Ubuntu 24.04`

搜索时可以逐步补充以下信息：

- 使用的系统：Windows、macOS、Ubuntu 等
- 使用的软件和版本
- 使用的编程语言或框架
- 完整报错信息
- 执行过的命令
- 预期结果与实际结果

### 优先查看哪些资料

资料的可靠性通常与来源有关，建议按以下顺序查找：

1. 官方文档和官方仓库。
2. 软件包或框架的官方示例。
3. GitHub Issues、Discussions 和 Releases。
4. 维护者或社区的技术讨论。
5. 个人博客、论坛和问答网站。

阅读教程时，需要确认文章对应的软件版本、操作系统和发布时间。旧版本配置可能已经失效，搜索结果中的代码也需要结合官方文档验证。

### 如何提出开发问题

一个清晰的问题至少包含以下内容：

1. 想完成什么目标。
2. 当前使用的系统、软件和版本。
3. 执行了什么操作或命令。
4. 出现了什么完整报错。
5. 预期结果是什么。
6. 已经尝试过哪些解决方法。
7. 哪些信息已经确认无误。

报错问题应尽量提供完整错误信息，不要只截取最后一行。代码问题应提供能够复现问题的最小代码片段，并删除 API 密钥、密码、Cookie、内网地址等敏感内容。

### 如何向 AI 提问

向 AI 提问时，需要明确任务、背景、限制和期望格式。信息越具体，得到的回答越容易验证和执行。

可以按照以下结构组织问题：

```text
目标：希望完成什么事情
背景：使用的系统、项目、软件和版本
现状：已经完成了什么，当前遇到什么问题
材料：相关代码、配置、日志或链接
限制：不能修改的文件、不能使用的方案或其他要求
输出：希望 AI 返回解释、步骤、代码、差异补丁还是排查结论
```

例如：

```text
目标：在 VuePress 网站中新增一个导航页面。
背景：项目使用 VuePress 2 和 pnpm，源码目录是 src/。
现状：navbar.ts 中已经有技术笔记、生活分享和项目展示。
要求：新增“开发指南”入口，创建对应页面，并保持现有导航不变。
限制：不要提交 Git，不要部署，只执行本地构建验证。
输出：请先检查相关文件，再修改源码，最后报告实际构建结果。
```

### 使用 AI 时需要保留判断

AI 可以帮助解释概念、搜索思路、编写代码和分析报错，但返回内容仍需要验证：

- 检查命令是否适用于当前系统。
- 检查软件版本是否匹配。
- 检查文件路径是否真实存在。
- 检查代码是否符合项目现有结构。
- 检查是否包含危险命令或敏感信息处理。
- 通过官方文档、实际运行结果或构建结果确认结论。

涉及删除文件、修改配置、部署服务、推送仓库和使用密钥的操作，需要明确影响范围后再执行。
