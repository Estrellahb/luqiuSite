云服务商的防火墙规则一般也叫安全组规则。它控制服务器哪些流量可以进来，哪些流量可以出去。常见场景里，服务器本机系统内还有一层防火墙，例如 `ufw`、`firewalld`、`iptables`，云服务商安全组属于更靠外的一层访问控制。

新建服务器后，安全组通常需要先确认 SSH、HTTP、HTTPS、ICMP、出站访问这几类规则。规则放得太宽，服务器会直接暴露在公网；规则收得太紧，部署、证书签发、接口访问和远程登录可能会失败。

## 常见规则配置

- 规则描述：ALLOW ALL OUT
  - 规则方向：出
  - 协议：all
  - 端口范围：1-65535
  - 授权IP：0.0.0.0/0

- 规则描述：RDP
  - 规则方向：入
  - 协议：rdp
  - 端口范围：3389
  - 授权IP：0.0.0.0/0

- 规则描述：SSH
  - 规则方向：入
  - 协议：ssh
  - 端口范围：22
  - 授权IP：0.0.0.0/0

- 规则描述：HTTPS
  - 规则方向：入
  - 协议：https
  - 端口范围：443
  - 授权IP：0.0.0.0/0

- 规则描述：HTTP
  - 规则方向：入
  - 协议：http
  - 端口范围：80
  - 授权IP：0.0.0.0/0

- 规则描述：ICMP
  - 规则方向：入
  - 协议：icmp
  - 端口范围：1-65535
  - 授权IP：0.0.0.0/0

## 修改建议

SSH 建议改成其他端口号。公网环境下，默认的 `22` 端口会持续受到扫描和爆破尝试。如果云服务商安全组仍然把 `22` 暴露给 `0.0.0.0/0`，登录入口会长期对整个公网开放。

更稳妥的做法是修改 SSH 服务端口，并在云服务商安全组中只放行新的 SSH 端口。若有固定办公网络或固定家宽出口，也可以把授权 IP 从 `0.0.0.0/0` 收窄到固定公网 IP 或对应网段。

SSH 端口修改前，需要确认新端口已经在云服务商安全组和服务器本机防火墙中放行。新端口登录测试成功后，再关闭旧的 `22` 端口规则，避免远程连接中断后无法重新登录。

## ALLOW ALL OUT

ALLOW ALL OUT 意思是默认出站端口全放行，服务器可以执行这些操作：

```bash
apt update
docker pull
curl 外部网站
访问 GitHub
访问证书服务
访问上游 API
```

出站规则对服务器部署影响很大。系统更新、Docker 镜像拉取、证书申请、对象存储上传、API 回调、WebHook 通知都依赖出站网络。如果出站规则被限制，需要按实际服务逐项放行目标端口。

常见出站访问包括：

- `80`：HTTP 请求、部分软件源访问
- `443`：HTTPS 请求、GitHub、Docker Registry、证书服务、API 服务
- `53`：DNS 查询
- `123`：NTP 时间同步
- `25` / `465` / `587`：邮件发送，部分云服务商默认会封禁 `25` 端口

普通 Web 服务器场景下，默认出站全放行使用成本最低。对安全要求更高的场景，可以按服务依赖逐步收窄出站范围。

## ICMP 入站

ICMP 入 意思是允许任何公网 IP 对服务器进行 ICMP 探测。

- `ping` 测试服务器是否通
- `traceroute` / `tracert` 查看路由路径

ICMP 对排查网络连通性很有用。服务器无法访问时，`ping` 可以快速判断公网 IP 是否可达，`traceroute` 可以观察路由在哪一段出现异常。

允许 ICMP 不等于开放业务端口。即使 ICMP 可达，HTTP、HTTPS、SSH 仍然需要对应端口规则放行。部分安全策略会关闭公网 ICMP，以减少被扫描时的可见性，但关闭后也会降低网络排查效率。

## HTTP 和 HTTPS 入站

HTTP 入站对应 `80` 端口，HTTPS 入站对应 `443` 端口。部署网站、反向代理、API 服务时，这两个端口通常需要对公网开放。

`80` 端口除了普通 HTTP 访问，还常用于 Let's Encrypt 的 HTTP-01 证书验证。如果使用 Certbot 通过 HTTP-01 方式签发证书，安全组需要临时或长期放行 `80` 端口。

`443` 端口用于 HTTPS 服务。Nginx、Caddy、Traefik 等反向代理通常会监听该端口，并把请求转发到后端服务。只部署 HTTPS 网站时，`80` 可以用于跳转到 `443`，也可以在证书签发完成后按需关闭。

## RDP 入站

RDP 对应 `3389` 端口，主要用于 Windows 服务器远程桌面。Linux 服务器通常不需要开放该端口。

如果服务器不是 Windows 系统，RDP 规则可以删除。若确实需要远程桌面访问，建议限制授权 IP，不建议长期对 `0.0.0.0/0` 开放。

## 云服务商防火墙与系统防火墙

云服务商安全组放行后，服务器本机防火墙也可能继续拦截流量。排查端口不通时，需要同时检查两层配置。

常见检查命令：

```bash
sudo ufw status
sudo iptables -L -n -v
sudo ss -lntup
```

`ss -lntup` 用来确认服务是否真的在监听目标端口。安全组只负责允许流量进入服务器，如果服务没有启动，端口仍然无法访问。

## 端口开放建议

公网服务器建议只开放实际需要的入站端口。

- Linux 服务器：优先开放 SSH 新端口、HTTP、HTTPS、ICMP
- Windows 服务器：按需开放 RDP，并限制来源 IP
- 纯内网服务：不对公网开放业务端口，通过内网安全组或 VPN 访问
- 临时调试端口：用完后及时关闭，避免测试服务长期暴露

安全组规则调整完成后，可以在本地使用 `curl`、`ssh`、`nc` 等命令测试连通性，也可以使用云服务商控制台提供的端口检测功能。
