# 开工前的现代开发工具箱配置

在完成技术选型并明确了开发全生命周期之后，很多初学者迫不及待地打开电脑准备开工。

但很多人很快就会在日常开发细节中陷入抓瞎：
- *"为什么老程序员写代码时，光标停在哪一行就能立刻看到哪里有语法错误，而我必须等到运行报错才发现拼错了单词？"*
- *"页面上的数据加载不出来，但我完全不知道浏览器到底有没有把请求发出去、后端究竟返回了什么状态码；"*
- *"写好了一个后端接口，难道每次测试都非得大费周章写个前端界面点按钮来测吗？"*
- *"代码把数据存进了数据库，但数据到底长什么样？我怎么能肉眼看到它？"*

工欲善其事，必先利其器。除了代码编辑器本身，现代专业开发者的电脑中还常驻着一套**标准化的辅助武器库**。

本篇我们将带你装配这套武器，学会使用现代开发者不可或缺的四大生产力利器。

---

## 一、代码编辑器宇宙中心：VS Code 黄金扩展配置

微软开源的 **Visual Studio Code（VS Code）** 凭借轻量、开源、极其庞大的插件生态，已成为全球占有率绝对第一的代码编辑器。

但在"纯毛坯房"状态下，VS Code 只是一个好用点的记事本。我们需要为其装配以下几款**必备的工业级黄金插件**（在 VS Code 左侧扩展市场 `Ctrl + Shift + X` 直接搜索安装）：

```text
┌───────────────────────────┬────────────────────────────────────────────────────────┐
│ 插件名称                  │ 核心功能与生产力收益                                   │
├───────────────────────────┼────────────────────────────────────────────────────────┤
│ Prettier - Code formatter │ 全球通用的代码格式化神器，保存文件时自动对齐缩进与换行 │
│ Error Lens                │ 语法高亮显微镜，把代码报错直接以醒目单行提示浮在代码旁 │
│ GitLens                   │ 代码历史透视眼，光标停留处以淡灰色文字静默显示作者历史 │
│ Path Intellisense         │ 路径自动补全器，写导入路径时自动弹出文件名列表候选     │
│ indent-rainbow            │ 彩虹缩进线，用不同颜色区分多层缩进嵌套，防代码看花眼   │
└───────────────────────────┴────────────────────────────────────────────────────────┘
```

### 生产力核心：开启“保存时自动格式化”（Format on Save）
许多新手写的代码排版混乱，有的行缩进 2 个空格，有的行缩进 4 个空格，极其难看且容易出错。

在 VS Code 中配置这个开关，能彻底解放你的强迫症：
1. 按快捷键 `Ctrl + ,`（macOS 为 `Cmd + ,`）打开设置面板；
2. 搜索框输入 `editor.formatOnSave`；
3. 勾选 **`Editor: Format On Save`**；
4. 搜索框输入 `default formatter`，在下拉菜单中选择 **`Prettier - Code formatter`**。

配置完成后，无论你写代码时排版有多乱，只要按下 **`Ctrl + S` 保存**，VS Code 会在 0.1 秒内自动把整份文件排得像大厂标准代码一样整齐！

## 二、前端与网络透视眼：浏览器开发者工具（F12 / DevTools）

任何一个现代浏览器（Chrome、Edge、Firefox）都内置了一套极其强大的工程级调试工作台。

在任意网页上按键盘的 **`F12`**（或鼠标右键点击「检查」），即可唤出 DevTools。其中开发者日常使用率最高的是以下三大面板：

```text
DevTools 核心面板分布
┌───────────┬─────────────┬───────────┬─────────────┬──────────┐
│ Elements  │ Console     │ Sources   │ Network     │ ...      │
│ (元素树)  │ (控制台日志)│ (断点调试)│ (网络流量抓包)│          │
└───────────┴─────────────┴───────────┴─────────────┴──────────┘
```

### 1. 网络抓包面板（Network 面板，重中之重）
当网页上的数据加载不出来、按钮点了没反应时，**第一反应永远是切到 Network 面板看流量**！
- **查看请求列表**：浏览器发送的每一个 HTTP/HTTPS 请求都会按时间顺序以流水线列出；
- **排查请求状态**：
  - 看到绿色的 `200` 代表请求成功打通并拿到数据；
  - 看到红色的 `404` 代表前端访问的 API 路径写错了，服务器根本不存在这个接口；
  - 看到红色的 `500` 代表后端代码在执行时崩溃抛异常了；
- **解剖单条请求细节**：
  - 点击任意一条请求，在右侧的 **Headers** 中可以查看完整 URL、请求方法（`GET`/`POST`）与鉴权 Token；
  - 在 **Payload / Request** 中查看前端传给后端的真实参数；
  - 在 **Response / Preview** 中查看后端实际返回的真实 JSON 数据结构。

::: info 终结“前后端扯皮”的铁证
在真实团队协作中，前端觉得后端没给数据，后端觉得前端没传参数。
打开 Network 面板，看一眼 Payload 和 Response，责任归属在 3 秒钟内立判高下。
:::

### 2. 控制台面板（Console 面板）
- 打印前端代码里所有的 `console.log()` 输出日志；
- 捕获前端未经处理的 JavaScript 运行时报错与语法异常；
- 允许你直接在当前网页上下文里敲代码进行即时试验。

### 3. 元素面板（Elements 面板）
- 实时展示当前页面的 HTML DOM 树结构与右侧对应的 CSS 样式盒模型；
- 双击即可现场篡改页面文字、临时修改 CSS 颜色和内外边距（仅限本地预览，刷新即还原），是前端调页面样式效率最高的方式。

## 三、后端接口与 API 调试利器：脱离前端单兵作战

在实际开发中，后端工程师往往比前端更早把接口写好。此时前端界面还没画出来，我们怎么验证这个接口好不好用？

必须依赖 **独立 API 调试工具**：

```text
[ 接口调试工具 (Apifox / Postman / curl) ]
               │
               ▼ 构造包含 Headers 与 JSON 参数的 HTTP 请求
     [ 后端 API 服务 (localhost:3000) ]
               │
               ▼ 返回处理结果 JSON
[ 实时在调试工具界面查看状态码与响应体 ]
```

### 1. 图形化接口管理工具（Apifox / Postman）
- **Postman**：全球历史最悠久的 API 调试黄金工具；
- **Apifox（目前国内团队极力推荐）**：集"API 文档定义 + 接口实时调试 + Mock 假数据生成 + 自动化测试"于一体的国产全能套件。
- **核心操作流**：
  1. 选择 HTTP 请求方法（`GET` / `POST` / `PUT` / `DELETE`）；
  2. 填入接口地址（如 `http://localhost:3000/api/v1/users`）；
  3. 在 Body 标签页中直接写入待测试的 JSON 数据；
  4. 点击蓝色的 **「Send（发送）」** 按钮；
  5. 界面下方立刻弹出后端真实的返回结果与耗时毫秒数。

### 2. 终端极简调试利器：`curl`
如果你在无图形界面的远程 Linux 服务器上，无法使用桌面软件，终端自带的 `curl` 指令就是最强大的接口测试武器：

```bash
# 发起一个简单的 GET 请求
curl -i https://api.github.com/users/octocat

# 发起一个带有 JSON 数据的 POST 请求
curl -X POST http://127.0.0.1:3000/api/v1/login \
     -H "Content-Type: application/json" \
     -d '{"email":"test@example.com","password":"123"}'
```
参数 `-i` 会把 HTTP 状态码、响应头（Headers）与数据体完整打印在终端上，是服务器排查网络连通性的终极法宝。

## 四、数据透视眼：数据库可视化客户端

程序运行产生的数据最终都要沉淀在数据库中。虽然可以通过终端敲 SQL 语句查看，但在日常开发中，使用 **图形化数据库客户端（GUI Client）** 能让你直接像看 Excel 表格一样翻阅数据库。

```text
┌───────────────────────────┬────────────────────────────────────────────────────────┐
│ 客户端软件                │ 特点与适用场景                                         │
├───────────────────────────┼────────────────────────────────────────────────────────┤
│ DBeaver (社区免费版)      │ 跨平台通用神器，基于 Java 开发，支持市面上几乎所有数据库│
│ Navicat                   │ 商业化数据库管理软件，交互成熟老牌，功能全面           │
│ VS Code 数据库插件生态    │ 如 Database Client、SQLite Viewer，直接在编辑器内看数据 │
└───────────────────────────┴────────────────────────────────────────────────────────┘
```

### 数据库客户端的核心价值：
1. **所见即所得的数据表浏览**：双击一张表，直接以表格形式呈现所有字段（ID、用户名、密码哈希、创建时间），支持单指点击直接修改数据；
2. **可视化的表结构设计器**：无需手动手敲长篇的 `CREATE TABLE` SQL，可以在图形界面里直接勾选添加字段、设置主键与自增规则；
3. **SQL 智能补全与执行器**：提供专门的 SQL 查询窗口，带语法高亮与自动补全，一键执行并导出为 CSV / Excel 文件。

## 五、现代开发者工作台全景拼装图

当这一套工具箱全部就位后，一个专业开发者的日常多屏或分屏作战界面通常是这样协同的：

```text
┌───────────────────────────────────────┬───────────────────────────────────────┐
│              代码与调试主屏幕          │               运行与观测副屏幕        │
│                                       │                                       │
│  [ VS Code 编辑器 ]                   │  [ 浏览器 + DevTools Network 抓包 ]   │
│  - 敲写核心业务代码与前端组件         │  - 实时渲染页面，排查接口网络数据流   │
│  - Prettier 自动格式化保证规范        │                                       │
│                                       │  [ Apifox / 数据库客户端 ]            │
│  [ VS Code 内置终端 / Linux 终端 ]    │  - 独立发送模拟请求测试新接口         │
│  - 运行开发服务 (pnpm dev / uv run)   │  - 实时翻阅数据表核对落盘记录         │
└───────────────────────────────────────┴───────────────────────────────────────┘
```

每一个工具都在其最擅长的领域各司其职，彼此咬合成为一条顺畅高效的**生产力飞轮**。
