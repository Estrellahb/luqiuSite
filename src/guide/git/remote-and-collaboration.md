# 远程联动与云端代码托管：VS Code 可视化实战

在前面的内容中，我们搞懂了 Git 的基本工作原理与三层状态流转。但如果每次提交代码、查看改动、推送到 GitHub 都必须在黑色窗口里手动敲击冗长的命令，不仅效率低下，而且极容易因为输错字母而报出一堆让人发懵的错误。

现代前端与后端开发早已迈入可视化时代。**主流代码编辑器 VS Code 原生内置了极其强大的「源代码管理」面板**，它将抽象的命令行变成了清晰直观的按钮、文件列表与红绿修改对比。

本篇我们将抛开繁琐的 Git Bash 终端，全程以 **VS Code 可视化界面** 为主视角，带你一步步完成"本地代码托管到 GitHub"与"从 GitHub 克隆项目"的全流程闭环。

---

## 一、认识 VS Code 的「源代码管理」中枢

用 VS Code 打开任意一个项目文件夹，在编辑器左侧的活动栏中，找到**三个圆点被线条连接的分支图标**（快捷键 `Ctrl + Shift + G` / macOS 快捷键 `Cmd + Shift + G`），这就是 Git 可视化控制台。

```text
VS Code 左侧活动栏
┌───┐
│ 📄│ 文件资源管理器
├───┤
│ 🔍│ 全局搜索
├───┤
│ 🌿│ 源代码管理 (Source Control)  ← 点击这里
├───┤
│ 🧩│ 扩展商店
└───┘
```

在这个面板中，所有 Git 状态全部被转化为了图形元素：
- **「更改（Changes）」列表**：对应工作区中被修改或新创建的文件；
- **「暂存的更改（Staged Changes）」列表**：对应已经执行了 `add`、准备打包的文件；
- **顶部多行输入框**：直接书写本次提交说明（Commit Message）；
- **右上角的对勾按钮（Commit）**：将暂存改动正式封存为本地快照。

## 二、单人日常流：在 VS Code 里点一点完成提交

你再也不需要在终端里敲 `git add` 和 `git commit` 了，所有操作都可以用鼠标直观完成：

### 1. 文件夹初始化为 Git 仓库
如果打开的是一个从未受版本控制的新文件夹，源代码管理面板中央会直接出现一个蓝色的 **「初始化仓库」（Initialize Repository）** 按钮。
- 点击该按钮，VS Code 会在后台自动完成 `git init`，即刻开启版本追踪。

### 2. 查看直观的红绿代码对比（Diff 视图）
在终端敲 `git diff` 看到的往往是刺眼的纯文本代码块。而在 VS Code 中：
- 直接鼠标**单击「更改」列表中的任意文件**；
- 编辑器中央会立刻弹出一分为二的 **双栏比对窗口（Diff View）**：
  - **左侧（原版）**：红色高亮标注被删除的行；
  - **右侧（当前）**：绿色高亮标注新增或修改的行。
- 你能一眼看清自己修改了哪些字符，再也不怕误改无辜代码。

### 3. 一键暂存（替代 `git add`）
- **暂存单个文件**：鼠标悬停在某个文件名右侧，点击出现的 **`+`（暂存更改）** 图标；
- **暂存全部文件**：鼠标悬停在「更改」这一栏大标题右侧，点击最右侧的 **`+`（暂存所有更改）** 按钮（等同于终端敲 `git add .`）。

文件被暂存后，会自动下沉移动到「暂存的更改」分组中。

### 4. 放弃不想要的修改（后悔药）
如果你在某个文件里改乱了代码，想彻底放弃改动、恢复成上一版的状态：
- 鼠标悬停在文件名旁，点击 **撤销箭头图标 `↩`（放弃更改）**；
- 确认弹窗后，该文件的所有修改会被立即清空，还原到上一次提交时的模样。

### 5. 编写说明并打包提交（替代 `git commit -m`）
1. 在面板顶部的文本框中，输入符合规范的提交信息（例如 `feat: 新增首页轮播图组件`）；
2. 敲键盘快捷键 `Ctrl + Enter`（macOS 为 `Cmd + Enter`），或者点击文本框上方的 **蓝色「提交（Commit）」对勾按钮**；
3. 暂存列表瞬间清空，改动正式写入本地版本库！

## 三、代码上云：一键发布到 GitHub

### 1. 登录与绑定 GitHub 账号
当你第一次在 VS Code 中使用云端功能时：
1. 点击 VS Code 左下角的「账户」齿轮/人像图标，选择「通过 GitHub 登录」；
2. 浏览器会自动弹出 GitHub 授权网页，点击绿色的「Authorize Visual-Studio-Code」；
3. 浏览器提示"正在重定向回 VS Code"，点击「打开」即可完成双向身份绑定。

### 2. 一键发布分支（Publish Branch）
当本地有了至少一次 Commit 之后，源代码管理面板中央会出现一个蓝色的 **「发布 Branch（Publish Branch）」** 按钮：

1. 点击 **「Publish Branch to GitHub」**；
2. 页面顶部会弹出下拉选项框，询问你想创建哪种类型的仓库：
   - **Publish to GitHub private repository**：发布为私有仓库（只有你自己能看，推荐）；
   - **Publish to GitHub public repository**：发布为公开仓库（全世界所有人都能浏览与下载）；
3. 选中后回车，VS Code 会在后台自动完成以下所有动作：
   - 自动在你的 GitHub 账号下创建同名仓库；
   - 自动绑定远程 `origin` 路径；
   - 自动把本地所有历史记录推送到云端！
4. 右下角弹出提示"已成功将分支发布到 GitHub"，点击右侧的「在 GitHub 上打开」，就能直接在网页端看到你刚才上传的代码了。

## 四、双向同步：日常的推送与拉取

将项目发布到云端后，源代码管理面板的提交按钮下方会出现一个带有旋转箭头的按钮：**「同步更改（Sync Changes）」**。

```text
┌──────────────────────────────────────────────┐
│  🔄 同步更改 (1 ↓  2 ↑)                      │
└──────────────────────────────────────────────┘
```

这个按钮直观展现了本地与云端的数据差距：
- **`2 ↑`（待推送）**：你在本地新完成了 2 次 Commit，尚未上传到云端；
- **`1 ↓`（待拉取）**：别人在云端提交了 1 次新修改，本地电脑尚未下载。

点击 **「同步更改」**，VS Code 会自动帮你在后台完成两步操作：
1. **先拉取（Pull）**：将云端的新改动下载并合并到本地；
2. **后推送（Push）**：将本地的最新快照上传到 GitHub。

整个流程全部封装在一个按钮中，完全无需在终端敲 `git pull` 或 `git push`。

## 五、如何从 GitHub 克隆（Clone）已有项目？

如果你在 GitHub 上看到了一个开源项目，或者需要把自己的旧项目下载到一台全新的电脑上：

1. 打开 VS Code（可以是一个完全空白的窗口）；
2. 按快捷键 `Ctrl + Shift + P`（macOS 为 `Cmd + Shift + P`）唤起命令面板；
3. 输入 `Git: Clone`（或者中文输入"克隆"），点击选中该命令；
4. 顶部弹出输入框，直接把 GitHub 仓库的 HTTPS 或 SSH 地址粘贴进去，回车；
5. 系统会弹出文件资源管理器窗口，选择你想将代码存放在电脑的哪个文件夹下（例如 `D:\Projects`）；
6. 下载完成后，VS Code 右下角会提示"是否要在新窗口中打开克隆的存储库？"，点击「打开」即可直接开始阅读和编写代码。

## 六、VS Code 动作与 Git 终端命令映射字典

为了让你在看别人的教程或技术文章时能无缝转换，我们把刚刚的所有图形化点击动作，与底层的终端命令整理了一张对照表：

| 你在 VS Code 中的操作 | 等同于在终端中执行的命令 |
| :--- | :--- |
| 点击「初始化存储库」按钮 | `git init` |
| 单击文件名查看左右红绿对比 | `git diff <file>` |
| 点击文件名右侧的 `+` 图标 | `git add <file>` |
| 点击「更改」分类右侧的大 `+` 图标 | `git add .` |
| 点击文件名右侧的撤销箭头 `↩` | `git restore <file>` |
| 输入说明后点击「√ 提交」按钮 | `git commit -m "说明文字"` |
| 点击「发布分支到 GitHub」 | `git remote add ... && git push -u origin main` |
| 点击「同步更改」按钮 | `git pull` 后紧接着 `git push` |
| 执行 `Git: Clone` 命令 | `git clone <URL>` |

::: tip 生产力插件推荐：GitLens 与 Git Graph
虽然 VS Code 原生功能已经足够应对 90% 的场景，但在扩展市场（Extensions）中，还有两个被全球开发者封神的 Git 辅助插件：
1. **GitLens**：安装后，只要光标停在代码的任意一行，行末就会以淡灰色文字静默显示：**这一行代码是谁在几月几号写的、当时的提交说明是什么**。在团队协作排查问题时堪称神器；
2. **Git Graph**：将整个仓库的所有分支演进、合并历史渲染为一张彩色的地铁线路图，每一个圆点就是一个 Commit，点击即可查看该次提交的所有变动文件。
:::
